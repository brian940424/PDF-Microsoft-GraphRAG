# 使用指南

## 建立專案並匯入文件

1. 開啟管理後台，在「0 專案與連線設定」建立專案，然後選取並開啟。
2. 在同一頁的「GraphRAG 共用連線設定」區塊輸入 API Base URL 與 API Key，選擇 Chat、Embedding 模型並測試連線。
3. 前往「1 文件與建圖」匯入 PDF。每份文件可以分別設定忽略頁首／頁尾比例及頁面範圍；起始頁和結束頁使用從 0 開始的索引，結束頁包含在範圍內。
4. 「前處理設定」的「Vision 模型」預設為 `gpt-6-luna`，「Vision 解析範圍」預設只送含圖表或表格的頁面；不需要時可選「停用」，只擷取 PDF 文字層。Vision 會將頁面影像送到共用連線設定的 API，表格轉成 Markdown、圖片與圖解改寫為文字描述；沒有文字層的頁面一律送出。單頁失敗會改用文字層，API Key 錯誤等每頁都會失敗的錯誤會立即停止並全部改用文字層，詳細結果記錄在專案的 `processed/report.json`。
5. 執行前處理並確認文件狀態，再建立 Graph。前處理與建圖都會顯示進度條，建圖日誌會持續更新。Documents 表的「前處理」「建圖」欄位會標示每份 PDF 的完成情況；「選擇要前處理／建圖的 PDF」預設選取尚未完成的檔案，可直接再按「開始前處理」或「建立 Graph」重新處理。若中斷或狀態停在索引中，先查看該頁日誌及專案的 `graphrag/` 狀態檔，再決定是否重建。

## 逐頁檢查前處理結果

1. 前處理完成後，展開「1 文件與建圖」最下方的「逐頁檢查」，選擇 PDF。
2. 頁面清單列出每頁的解析方式（Vision、文字層、Vision 失敗→文字層、空白、錯誤）、是否已檢查、是否已修改及字元數；可用「篩選頁面」只看未檢查或 Vision 失敗的頁面。點選列、按上一頁／下一頁（只在篩選結果內移動）或輸入頁碼後按 Enter 可切換頁面。
3. 左側是 PDF 原頁，右側是送去建圖的文字，可直接修改後按「儲存並標示已檢查」。內容與解析結果不同時會標示為「已修改」。
4. 「重跑 Vision（本頁）」使用「前處理設定」選的 Vision 模型，「改用文字層」重新擷取 PDF 文字層；兩者只把結果放進編輯框，按儲存才會寫入。「還原為解析結果」會捨棄手動修改。
5. 重新前處理時，已修改的頁面保留手動內容；若新的解析結果與修改當時不同，會顯示「⚠️ 解析結果已變」提醒確認。未修改但已檢查的頁面，若解析結果改變，會變回未檢查。重新匯入或刪除 PDF 時會清除該 PDF 的修改。
6. 修改後該 PDF 的「建圖」欄會變回未建圖，需重新建立 Graph 才會套用。

建圖會呼叫 LLM 與 Embedding API，費用與等待時間依文件量和供應商計價而異。掃描影像 PDF 沒有文字層，需啟用 Vision 才能取得內容；Vision 依送出的頁數另外計費。

## 單次問答與 Evidence

在「2 問答測試」輸入問題，選擇回答模型、檢索策略與回答格式，再送出查詢。檢索策略可選「自動」（預設，由回答模型依問題判斷並顯示「自動 → 實際策略」與選擇原因，會多一次 LLM 呼叫）或直接指定 Local／Global／DRIFT／Basic。回答以外，頁面也會顯示查詢 Context、Evidence 清單及選取證據的原文（可取得時包含文件、頁碼、Chunk 等資訊）。Evidence 是程式從 GraphRAG 查詢回傳的 Context 解析，不是模型回答中自行生成的來源標籤。

要回顧之前的問答，展開頁面下方的「歷史紀錄」，點選一列即可載回該次的問題、查詢方法、回答格式、回答與 Evidence，可直接修改問題再送出。清單只列手動問答，自動問答測試與檢索實驗的紀錄不會出現在這裡。

一般入口只提供使用者問答，管理後台需先將專案建圖完成並啟用一般使用者查詢。

## 自動問答測試（分頁 3）

自動問答頁分為生成題目、生成回答和評測回答幾個步驟：

1. 從「選擇已存在的題目集」選取專案內已儲存的題目集（含「4 檢索實驗」匯入的），或匯入題目集，或設定每份 PDF 的題數與生題模型後生成題目。開啟專案時預設載入最近的題目集。生題和答案來源可在題目表格修改，並匯出 JSON。
2. 設定回答模型、檢索方式、回答格式及回答請求並行數，執行生成回答。生成完成前評測不可執行。檢索方式可選「自動」，每題由回答模型選擇策略；也可選「Agentic Search（實驗）」，由 Agent 根據搜尋證據決定是否補搜一次。Agentic Search 會增加模型呼叫與延遲。結果表的「實際檢索策略」欄會顯示所用策略；Gold Evidence Retrieval 指標可用於 Agentic 已保存的文件／頁碼來源，不代表策略品質已經資料集驗證。
3. 設定評測模型及評測並行數，再執行評測。結果表顯示系統回答、標準答案、判斷和理由。
4. 人工調整判斷時，該筆評判理由會清空，正確率會自動重算。

生成答案與評測分開執行；回答會保存於目前專案，重新開啟專案後仍可繼續評測。

## 檢索實驗（分頁 4）

1. 匯入一個或多個題目集。再次匯入時會以所選題目集取代原有匯入題目，不會累加舊題目。
2. 新增實驗組後，在各組卡片內選擇回答模型、策略與回答格式。選擇策略後會顯示其專屬參數；參數是依實驗組和策略分開保存的。策略也可選「自動」，每題由回答模型選擇策略，逐題結果會顯示實際策略與原因。
3. 設定全域評測模型、評分方式和測試最大並行請求數。先按「檢索並生成答案」，完成後再按「評測答案」。可停止實驗，已完成逐題結果會保留。
4. 查看實驗組摘要、實驗組 × 題目集摘要和逐題結果。逐題等級 0／1／2 可人工修改並更新摘要。
5. 匯出精簡摘要 JSON 和逐題結果 JSON。

策略可調項與指標意義詳見[檢索實驗與策略參數](檢索實驗與策略參數.md)。題目集資料欄位詳見[題目集 JSON 格式](題目集格式.md)。

## 常見狀況

- 「沒有可選專案」：確認專案已開啟；一般入口另要求索引完成並啟用查詢。
- 「尚未生成答案」：先在檢索實驗完成回答生成，等待狀態顯示完成後再評測。
- Recall／MRR 等來源指標不可計算：通常是該策略沒有可可靠映射的排序來源，或題目缺少來源頁碼。系統不會推測排名或虛構命中。
- API Key 重啟後消失：確認環境變數、`.env` 或 `PROJECTS_ROOT/.connection.json` 設定，並確保重新啟動時使用相同 `PROJECTS_ROOT`。
