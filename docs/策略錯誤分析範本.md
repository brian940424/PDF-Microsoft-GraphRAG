# 搜尋策略錯誤分析範本

本表用於執行[搜尋策略優化與擴充任務書](搜尋策略優化與擴充任務書.md) Phase 0。每列代表一個問題與一種搜尋方法的結果；同一問題比較多種方法時，請分列填寫並使用相同的 `case_id`。此範本不包含虛構題目或基準答案。

## 標註欄位

| 欄位 | 填寫方式 |
| --- | --- |
| `case_id`、`question_id`、`method` | 問題識別碼、題目集題號、策略（`local`／`global`／`drift`／`basic`／`auto`／`agentic`） |
| `question_type` | `exact_lookup`、`entity_procedure`、`multi_step_diagnosis`、`cross_system`、`table_or_figure`、`no_answer_or_ambiguous`、`conflicting_sources` |
| `answer_grade` | `correct`、`partial`、`wrong`、`unanswerable`；依必要答案要點判定，不以措辭相似度單獨判斷 |
| `evidence_grade` | `supports`、`partial`、`does_not_support`、`missing`；確認取回的來源是否直接支持回答，並保留文件與頁碼 |
| `primary_failure_stage` | `none`、`routing`、`preprocessing`、`indexing`、`retrieval`、`evidence_mapping`、`answer_generation`、`question_or_gold`、`review_disagreement` |
| `secondary_failure_stages` | 可留白；若有多個成因，以分號分隔上述階段 |
| `gold_evidence`、`retrieved_evidence` | 填文件名稱與頁碼；若為 Community Report，註明 `community_report`，不可編造 PDF 頁碼 |
| `reviewer`、`review_notes` | 記錄人工覆核者、錯誤歸因依據、歧義或來源衝突 |

## 歸因判定順序

1. 先核對原始 PDF 與逐頁前處理結果：必要內容未進入文字層／Vision 轉寫時，主因標為 `preprocessing`。
2. 前處理有內容但 GraphRAG 索引缺少必要資料時，標為 `indexing`。
3. 索引含有 Gold Evidence，但搜尋結果沒有取回時，標為 `retrieval`；只有 Auto 選錯策略且固定策略能取回時，才以 `routing` 為主因。
4. 有取回內容但來源 ID、文件或頁碼無法正確還原時，標為 `evidence_mapping`。
5. 來源已支持答案要點但回答漏答、誤解或加入無根據內容時，標為 `answer_generation`。
6. 標準答案、必要要點或 Gold Evidence 本身不明確時，標為 `question_or_gold`；評審者對支持度或答案等級無法一致時，標為 `review_disagreement`，交由第二位人工覆核。

策略選錯不能只憑模型理由判定：須使用同一題目、同一索引和相同回答設定重跑固定策略作對照，並檢查各策略實際取回的 Evidence。

## 比較時需固定的條件

- 記錄索引／前處理版本、回答模型與推理深度、回答格式、策略參數、評測時間及題目集版本。
- Local、Global、DRIFT、Basic、Auto 使用相同題目和回答設定；Agentic 以實驗組另列，記錄每步方法、補搜原因、搜尋步數、模型呼叫數、延遲及錯誤。
- Gold Evidence 由人工逐題核對來源文件與頁碼；抽樣由第二人覆核。沒有 Gold Evidence 的題目只用於拒答評測，不計入 Evidence 命中指標。
- 留出未用於調整策略或 prompt 的 holdout 題目，最終比較前先約定品質與成本門檻。
