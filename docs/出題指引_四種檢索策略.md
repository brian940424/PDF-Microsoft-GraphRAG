# 出題指引：四種檢索策略

本指引給負責準備題目集的出題者。「4 檢索實驗」會用同一份題目集比較 GraphRAG 的 **Basic、Local、Global、DRIFT** 四種檢索策略。為了看出各策略的強弱，題目集需要涵蓋四種題型，每題也要標明是針對哪種策略設計的。

題目集 JSON 的欄位規則見 [題目集格式.md](題目集格式.md)。

---

## 一、先判斷：這題屬於哪一種？

照順序問自己下面四個問題，第一個答「是」的就是該題的類型：

| 順序 | 判斷問題 | 是 → 類型 |
|---|---|---|
| 1 | 答案是否需要綜觀**整份手冊（或多份手冊）**做歸納、分類、比較，而不是找某一段？ | **Global** |
| 2 | 答案是否必須**串接兩個以上不同章節**的資訊，前一步的結果決定下一步要查什麼？ | **DRIFT** |
| 3 | 題目是否主要在問**兩個以上具名元件／功能／系統之間的關係或互相影響**？ | **Local** |
| 4 | 其他：答案寫在手冊**同一節**裡（步驟、條件、數值、警告、代碼、定義、設定路徑） | **Basic** |

> 不確定時歸為 Basic。實務上大多數手冊問題都是 Basic 題，這也是系統「自動」策略的預設判斷。

---

## 二、各策略的出題條件與指令

### 1. Basic：單點查找題

**策略原理**：以向量相似度找出和題目最像的幾段原文，直接根據原文回答，能精確引用頁碼。

**出題條件（全部符合）**

- 答案完整寫在手冊**同一節**內（可跨相鄰 1–2 頁）。
- 問的是具體內容：操作步驟、設定路徑、規格數值、警告／注意事項、錯誤代碼意義、名詞定義、適用條件。
- 有唯一明確的標準答案，不需要推論或整合。

**不要出成 Basic 的情況**

- 需要翻到另一章才能答完 → 改成 DRIFT。
- 問「有哪些類型」「整體來說」 → 改成 Global。

**出題指令**

```
請從手冊中挑選一個段落，出一題 Basic 單點查找題：
1. 答案必須完整出現在同一節（最多跨相鄰兩頁），不需要參考其他章節。
2. 題型限於：操作步驟、設定路徑、規格數值、警告或注意事項、錯誤代碼、名詞定義、適用條件。
3. 題目用一般使用者的口吻提問，不要直接照抄章節標題或原文句子，
   以測試檢索是否能理解同義說法。
4. 標準答案依原文改寫成完整句子，步驟題要保留所有必要步驟及順序，
   數值要附單位與條件。
5. 記錄題目來源頁（question_sources）與答案來源頁（answer_sources）。
```

**範例**

- 「前碟煞來令片的新品厚度和磨耗極限各是多少？」
- 「BCM 的自動上鎖功能出廠預設在什麼條件下上鎖？」

**加分難度（選用）**：刻意挑選手冊中有**相似項目**的段落（例如前碟煞與後碟煞的規格、QR25DE 與 VQ35DE 的程序），題目寫清楚是哪一個，用來測試是否會找錯段落。

---

### 2. Local：實體關係題

**策略原理**：先找出和題目最相關的實體（元件、功能、系統），再沿著知識圖譜擴展到它們的關係、社群報告與部分原文。擅長回答「誰跟誰有關」，但常找不到單一步驟或數值的精確段落。

**出題條件（全部符合）**

- 題目**明確點名兩個以上**元件、功能、訊號或系統。
- 問的是它們之間的**關係**：相依、互斥、影響、連動、共用、前提條件。
- 答案的資訊分散在這些實體各自的說明中，而非單純一段步驟。

**不要出成 Local 的情況**

- 只點名一個功能並問操作步驟或數值 → 這是 Basic。
- 需要多步推理才能串起因果 → 這是 DRIFT。

**出題指令**

```
請出一題 Local 實體關係題：
1. 從手冊中找出兩到三個彼此有關聯的具名元件、功能或系統。
2. 題目必須點出這些實體的名稱，並詢問它們之間的關係，例如：
   「開啟 A 會對 B 造成什麼影響？」「A 與 B 能否同時使用？」
   「要使用 A 需要先具備哪些功能或設定？」
3. 答案的依據可以分散在不同段落，但每個實體的相關說明都要能在手冊中找到。
4. 標準答案要寫出每個實體在關係中的角色，以及關係成立的條件。
5. answer_sources 列出所有用到的頁碼（可包含多頁）。
```

**範例句型**

- 「BCM 進入低耗電模式時，IPDM E/R 和組合儀表扮演什麼角色？」
- 「要拆煞車踏板總成，必須先處理哪個其他總成？那個總成有哪些限制？」

---

### 3. Global：全域歸納題

**策略原理**：對整個知識圖譜的社群報告做 Map-Reduce，先分段摘要再整合。擅長回答整體性、歸納性的問題，**但不會引用原文頁碼**。

**出題條件（全部符合）**

- 答案需要綜觀**整份手冊或多份文件**，無法從單一段落取得。
- 問法屬於：概覽、主題分類、彙整清單、跨系統比較、「有哪些類型／種類」、「主要涵蓋哪些面向」。
- 標準答案是**要點清單**，評分看要點涵蓋率，而非逐字比對。

**不要出成 Global 的情況**

- 雖然問「有哪些」，但其實手冊某一節就有完整清單 → 這是 Basic（例如「後窗除霧計時器有哪些模式」，BCS p.16 的一張表就列完了）。

**出題指令**

```
請出一題 Global 全域歸納題：
1. 題目必須需要綜觀整份手冊（或全部文件）才能回答，
   答案不能直接出現在某一節的現成清單中。
2. 問法為概覽、分類、彙整或比較，例如：
   「這套維修手冊共有哪些類別的作業注意事項？各出現在哪些手冊？」
   「更換 A 控制單元與更換 B 控制單元的後續作業有什麼異同？」
3. 標準答案寫成 3–8 個要點，每個要點一句話；只列手冊有依據的要點，
   不要加入一般常識。
4. 在 answer_aliases 中可以列出用不同分類方式整理的等價答案。
5. answer_sources 盡量列出各要點的出處頁；即使 Global 不回報頁碼，
   這些資料仍可供人工覆核。
```

**注意**：Global 回答不會附頁碼，因此 Global 題的來源指標（Evidence Hit Rate 等）不會計算，只看答案得分。

---

### 4. DRIFT：多步推理題

**策略原理**：先用社群報告建立整體脈絡，再自動產生追問子問題，用局部搜尋逐輪補足細節。適合需要「廣度＋深度」的複雜問題，**也是最慢、最貴的策略**。

**出題條件（全部符合）**

- 答案必須**結合兩個以上不同章節或主題**的資訊。
- 存在推理鏈：先從 A 得知某結果或條件，才知道要去 B 查下一步。
- 典型情境：因果鏈、跨系統故障診斷、「若 A 發生，接著應該怎麼辦，又會影響什麼」。

**不要出成 DRIFT 的情況**

- 單一設定、單一選單路徑或同一節內的連續步驟，即使題目有「觸發條件」或「多個步驟」，都還是 Basic。
  例如：「更換煞車油時，加注步驟為何？」雖然有多個步驟，但都寫在 BR p.14 同一節，所以是 Basic，不是 DRIFT。

**出題指令**

```
請出一題 DRIFT 多步推理題：
1. 先在手冊中找出至少兩個不同章節，且它們之間有因果或先後依賴關係
   （例如章節 A 描述某現象的原因，章節 B 描述該原因的處理方式）。
2. 題目從使用者遇到的情境出發，回答時必須先推出中間結論，
   再用中間結論查到最終答案；只看其中任何一個章節都無法答完整。
3. 不要在題目中直接寫出中間結論，否則就退化成單點查找題。
4. 標準答案依推理順序寫出：中間結論 → 最終答案，每一步都需有手冊依據。
5. answer_sources 必須列出所有涉及章節的頁碼（至少兩個不相鄰的頁段）。
6. 另外在出題紀錄中寫下推理鏈（第一步查哪裡、得到什麼、第二步查哪裡），
   方便日後判斷模型是在哪一步出錯。
```

**範例句型**

- 「車輛無法起動，BCM 同時出現多個 DTC，應先處理哪一個？它為什麼會造成無法起動？」
- 「拆卸 A 總成時會動到 B 零件；裝回後因為 B 被拆過，還要執行什麼程序？」

## 三、範例題組（以 SM3E-1L33U3 維修手冊為例）

以下例題取自 SM3E-1L33U3 專案的六份維修手冊：ACC（加速控制）、AV（音響與導航）、BCS（車身控制）、BR（煞車）、BRC（煞車控制）、BRM（車身修理）。標準答案都已逐頁對照手冊原文，頁碼為 PDF 頁碼，文件名稱即 `ACC.pdf`、`BR.pdf` 等。

### 範圍：單頁、跨頁、跨檔案

除了策略類型，每題還要標明答案的範圍：

| 範圍 | 定義 | 適合的策略 |
|---|---|---|
| 單頁 | 答案全部在同一頁 | Basic、Local |
| 跨頁 | 答案在同一份手冊的兩頁以上（相鄰或不相鄰） | 四種皆可；DRIFT 應選不相鄰的頁 |
| 跨檔案 | 答案需要兩份以上手冊 | Local、Global、DRIFT；Basic 不出跨檔案 |

**找跨檔案題的訣竅**：SM3E 手冊常寫「Refer to ACC-3」這類交叉引用，跟著引用就能找到跨檔案的關聯（例如 BR 拆煞車踏板時引用 ACC 的加速踏板拆卸）。另外，各手冊開頭的 PRECAUTION 章節內容相近，適合出跨檔案的 Global 題。

### Basic 範例

**B1｜規格數值｜單頁**
- 題目：前碟煞來令片新品的標準厚度是多少？磨到多薄就必須更換？
- 標準答案：新品標準厚度 11.0 mm（0.433 in），磨耗極限厚度 2.0 mm（0.079 in）。
- 答案來源：BR.pdf p.49
- 為什麼是 Basic：答案就在規格表的同一列。同頁還有後碟煞規格，可以測試是否把前、後搞混。

**B2｜警告事項｜單頁**
- 題目：保養時要清掉前後煞車上的粉塵，可以用壓縮空氣吹嗎？
- 標準答案：不可以。應使用真空集塵器清除前、後煞車的粉塵，嚴禁用壓縮空氣吹除。
- 答案來源：BR.pdf p.3
- 為什麼是 Basic：單一警告寫在 Precaution for Brake System 同一段。

**B3｜設定選項｜單頁**
- 題目：BCM 的自動上鎖功能（AUTO LOCK FUNCTION）出廠預設在什麼條件下上鎖？另一個可選的模式是什麼？
- 標準答案：初始設定 MODE1：車速達到 24 km/h（15 mph）時自動上鎖。MODE2：排檔從 P 檔移出時自動上鎖。MODE3 不使用，也可設為 Off。
- 答案來源：BCS.pdf p.16
- 為什麼是 Basic：答案在 Work Support 的同一張表。同頁還有 AUTO UNLOCK 的類似表格，可以測試是否找錯表。

**B4｜必要程序｜單頁**
- 題目：加速踏板位置感知器的線束接頭拔開過之後，必須做什麼？
- 標準答案：必須執行「加速踏板釋放位置學習」（Accelerator pedal released position learning），QR25DE 參照 EC-177、VQ35DE 參照 EC-680 的 Work Procedure。另外，加速踏板應能順暢回到完全放開的位置。
- 答案來源：ACC.pdf p.4
- 為什麼是 Basic：單一注意事項寫在同一段，答案還帶有引擎型號差異，可以測試是否漏答。

**B5｜操作步驟｜跨頁**
- 題目：煞車系統排氣時，乙烯管要先接在哪一個卡鉗？每個卡鉗的排氣步驟是什麼？
- 標準答案：
  1. 作業前將點火開關轉至 OFF，並拔開 ABS 作動器與電子單元（控制單元）的接頭，或拆下電瓶負極。
  2. 將乙烯管接到右後卡鉗的排氣閥。
  3. 將煞車踏板完全踩到底 10 次。
  4. 踩住煞車踏板，鬆開排氣閥排出管路中的空氣，然後立即鎖緊。
  5. 重複步驟 3、4，直到管路中沒有空氣。
  6. 將排氣閥鎖到規定扭力（前碟煞參照 BR-36，後碟煞參照 BR-39）。

  排氣時要注意主缸的油位。
- 答案來源：BR.pdf p.14–15
- 為什麼是 Basic：步驟屬於同一節，只是剛好跨到下一頁，可以測試檢索是否能把相鄰頁一起取回。

**✗ 反例（看起來像 DRIFT，其實是 Basic）**：「更換煞車油時，加注步驟為何？」雖然有踩踏板、鬆排氣閥、踩到全行程 2/3、鎖緊等多個步驟，但都寫在 BR p.14 同一節，所以是 Basic。

### Local 範例

**L1｜拆卸相依｜跨檔案**
- 題目：拆卸煞車踏板總成時，必須先拆下哪一個其他踏板總成？拆下的那個總成在處理上有什麼限制？
- 標準答案：拆煞車踏板總成的第 2 步要先拆下加速踏板（參照 ACC-3）。加速踏板總成不可分解、不可摔落或撞擊，也不可接觸水。
- 答案來源：BR.pdf p.18、ACC.pdf p.3
- 為什麼是 Local：問的是「煞車踏板總成」和「加速踏板總成」兩個實體之間的相依關係，而兩者的說明分屬兩份手冊。

**L2｜工具與控制單元的互相影響｜單頁**
- 題目：從資料連結接頭拔下 CONSULT 車輛介面（VI）後，跟 BCM 的睡眠模式有什麼關係？
- 標準答案：拔下 CONSULT VI 後，必須將點火開關依序切換 OFF → ON（至少 5 秒）→ OFF。若沒有這樣做，BCM 可能無法進入睡眠模式，進而可能造成電瓶放電。
- 答案來源：BCS.pdf p.14
- 為什麼是 Local：問的是「CONSULT VI」、「點火開關」和「BCM 睡眠模式」三者之間的關係。

**L3｜控制單元之間的協作｜跨頁**
- 題目：BCM 進入低耗電模式的過程中，IPDM E/R 和組合儀表扮演什麼角色？
- 標準答案：
  - BCM 會對點火開關 OFF 時仍在運作的單元（IPDM E/R 與組合儀表）發出睡眠請求。
  - BCM 透過 CAN 從這兩個單元收到睡眠就緒訊號（ready）；CAN 睡眠條件全部成立時，BCM 對各單元送出睡眠訊號，各單元就停止 CAN 傳輸。
  - BCM 睡眠條件也成立時，BCM 進入低耗電模式，各開關的讀取間隔從 10 ms 改為 60 ms。
- 答案來源：BCS.pdf p.12–13
- 為什麼是 Local：問的是三個具名控制單元之間的訊號往來與協作關係。

**L4｜零件之間的位置關係｜跨頁**
- 題目：調整煞車踏板時，停車燈開關、ASCD 取消開關和煞車踏板支架之間要怎麼定位？間隙標準是多少？
- 標準答案：先將兩個開關各逆時針轉 45° 鬆開。調好踏板高度後，用手拉住踏板，將兩個開關壓到螺紋末端碰到煞車踏板支架，再各順時針轉 45° 固定。止動支架（C₁）與兩個開關螺紋末端（C₂）的間隙標準為 0.74–1.96 mm（0.0291–0.0772 in）。放開踏板時，停車燈必須熄滅。
- 答案來源：BR.pdf p.13、p.48
- 為什麼是 Local：問的是三個零件之間的位置關係。程序在 p.13，間隙數值則要依「Refer to BR-48」到規格頁查。

**✗ 反例（看起來像 Local，其實是 Basic）**：「前碟盤的最大偏擺量與厚度差限制各是多少？」雖然提到偏擺和厚度兩個項目，但都只是同一張規格表（BR p.49）上的數值，所以是 Basic。

### Global 範例

**G1｜各手冊共通規定｜跨檔案**
- 題目：這套維修手冊中，哪些手冊提醒了使用氣動或電動工具、鐵鎚時的 SRS 安全規定？規定的內容是什麼？
- 標準答案：
  - ACC、AV、BCS、BR、BRC、BRM 六份手冊的 PRECAUTION 章節都有這項規定。
  - 點火開關 ON 或引擎運轉時，不可在氣囊診斷感知器等氣囊系統感知器附近使用氣動或電動工具，也不可用鐵鎚敲擊，以免振動觸發感知器、使氣囊展開。
  - 使用氣動、電動工具或鐵鎚前，一律先將點火開關轉至 OFF、拆下電瓶，並等待至少 3 分鐘。
- 答案來源：ACC.pdf p.2、AV.pdf p.8、BCS.pdf p.3、BR.pdf p.3、BRC.pdf p.4、BRM.pdf p.3
- 為什麼是 Global：要確認整套手冊中所有出現這項規定的地方，再歸納出共通內容。

**G2｜分類彙整｜跨檔案**
- 題目：這套維修手冊的 PRECAUTION 章節共有哪些類別的注意事項？各出現在哪些手冊？
- 標準答案（依各手冊目錄整理）：
  - SRS（氣囊與安全帶預縮器）：六份手冊都有
  - Brake System（煞車系統）：BR、BRC
  - Procedure without Cowl Top Cover（拆下前圍上蓋時的作業）：BR
  - Brake Control（煞車控制）、CAN System（CAN 系統）：BRC
  - Work（一般作業）：AV、BRC
  - Harness Repair（線束修理）、Trouble Diagnosis（故障診斷）：AV
  - Plastics（塑膠件處理）、High Strength Steel（高強度鋼修理）：BRM
- 答案來源：六份手冊 p.1 的目錄（ACC、AV、BCS、BR、BRC、BRM）
- 為什麼是 Global：答案必須綜觀全部手冊才能整理出分類，不存在於任何一頁。

**G3｜跨系統比較｜跨檔案**
- 題目：更換 BCM 與更換 AV 控制單元時，需要的額外作業有什麼相同和不同？
- 標準答案：
  - **共同**：更換前用 CONSULT 的「Before Replace ECU」保存或列印目前的車輛規格；無法使用時，更換後改用「After Replace ECU」或「Manual Configuration」。更換後必須在「Re/Programming, Configuration」中依序完成「After Replace ECU」，寫入車輛規格。
  - **BCM 特有**：必須執行系統初始化（NATS）；若新 BCM 沒有附遙控鑰匙，所有既有的遙控鑰匙都要重新登錄。
  - **AV 控制單元特有**：最後要做作業檢查，確認 AV 控制單元及倒車影像（固定導引線）正常。
- 答案來源：BCS.pdf p.63、p.79；AV.pdf p.336
- 為什麼是 Global：屬於跨系統比較，要從兩份手冊各自的程序中歸納出異同。

**✗ 反例（看起來像 Global，其實是 Basic）**：「後窗除霧計時器（SET R-DEF TIMER）有哪些模式？」雖然問「有哪些」，但 BCS p.16 的一張表就列完了，所以是 Basic。

### DRIFT 範例

**D1｜拆卸連帶的後續程序｜跨檔案**
- 題目：VQ35DE 車型拆裝煞車助力器後，除了助力器本身的檢查，還需要額外執行什麼學習程序？為什麼？
- 標準答案：
  1. VQ35DE 拆卸煞車助力器的第 4 步要拆下加速踏板總成（參照 ACC-3）（BR p.30）。
  2. 拆加速踏板總成的第 1 步是拔開它的線束接頭（ACC p.3）。
  3. 加速踏板位置感知器的線束接頭拔開過，就必須執行「加速踏板釋放位置學習」，VQ35DE 參照 EC-680 的 Work Procedure（ACC p.4）。
- 答案來源：BR.pdf p.29–30、ACC.pdf p.3–4
- 推理鏈：BR 助力器拆卸步驟 → 發現要拆加速踏板 → ACC 拆卸要拔接頭 → ACC 規定拔接頭後要做學習。題目沒有提到加速踏板，必須自己推出來。

**D2｜故障診斷的優先順序｜跨頁**
- 題目：車輛無法起動，CONSULT 顯示 BCM 同時有 B2562、U1000、B2190 三個 DTC。應該先處理哪一個？它為什麼會讓車輛無法起動？第一步要檢查什麼？
- 標準答案：
  1. 依 DTC 檢查優先順序表，B2562（LOW VOLTAGE）是第 1 優先，U1000 是第 2，B2190 是第 3（p.50）。
  2. B2562 的失效保護是禁止引擎起動，電源電壓回升到 8.8 V 以上 100 ms 後才會解除（p.49）。
  3. B2562 的偵測條件是 BCM 電源電壓低於 8.8 V 持續 120 秒以上，可能原因是電源電路的線束或接頭，或車輛電瓶（p.70）。
  4. 診斷第一步是檢查電瓶電壓；低於 8.8 V 就先充電再重新測試（p.70）。
- 答案來源：BCS.pdf p.49–50、p.70
- 推理鏈：先查優先順序表決定處理 B2562 → 查失效保護表了解為何無法起動 → 再到 B2562 的診斷程序查偵測條件與第一步。

**D3｜症狀 → 原因 → 原理｜跨頁**
- 題目：導航畫面上的車輛位置精度很低，可能有哪些原因？如果是 GPS 衛星標示一直呈灰色，又該怎麼處理？
- 標準答案：
  1. 精度低的原因（p.277）：
     - GPS 衛星標示呈灰色，無法確定目前位置。
     - 因為加裝雪鏈或系統用在別台車上，車速脈衝的設定與實際車速有偏差。處理方式：以約 30 km/h 行駛約 30 分鐘，系統會自動修正；若仍有偏差，用診斷功能的 CONFIRMATION/ADJUSTMENT 模式做距離調整。
     - 地圖資料錯誤或遺漏，車標總是偏到同一位置；原則上每年會發行一次更新的地圖。
  2. GPS 衛星標示呈灰色時（p.276）：
     - 車輛在建築物內或後方 → 移到空曠處。
     - 儀表板上方放了障礙物 → 不要在儀表板上放東西。
     - 目前位置看不到衛星 → 移動車輛，等到能看到衛星。
  3. 原理（p.211）：GPS 接收器收不到衛星電波時不會定位，例如在隧道內、建築物內停車、高架道路下，或 GPS 天線上放了物品。
- 答案來源：AV.pdf p.277、p.276、p.211
- 推理鏈：先查「精度低」的原因表 → 其中一個原因是「灰色標示」，再查灰色標示的原因與處理 → 最後到系統說明章節查 GPS 收不到訊號的原理。

**✗ 反例（看起來像 DRIFT，其實是 Basic）**：「DTC B2562 的偵測條件是什麼？」雖然是故障診斷題，但只問偵測條件，答案在 BCS p.70 一頁內，所以是 Basic。

## 四、所有題目共通規則

1. **答案必須有手冊依據**：不收錄需要一般常識或手冊外資訊才能回答的題目。
2. **一題只問一件事**：Global、DRIFT 題可以有多個要點，但都要回應同一個主問題。
3. **避免照抄原文**：題目用使用者的自然問法，否則所有策略都靠字面比對就答對，無法比較差異。
4. **標準答案要完整**：評分時，流程題漏掉必要步驟最高只能拿 3 級，所以標準答案本身一定要列出全部必要步驟與條件。
5. **機型或版本差異要寫明**：手冊對不同機型有不同說法時，題目要指定機型，或在標準答案中分別列出。
6. **來源頁碼要準確**：`question_sources`、`answer_sources` 的頁碼是 PDF 頁碼，用來計算來源命中率。

## 六、交付格式

題目集 JSON 只接受 [題目集格式.md](題目集格式.md) 列出的欄位，**不能加入「策略類型」欄位**，否則匯入會失敗。請另外附一份對照表，記錄每題的設計類型與範圍：

| number | 設計類型 | 範圍 | 推理鏈／備註（DRIFT 必填） |
|---|---|---|---|
| 1 | Basic | 單頁 | — |
| 2 | Local | 跨檔案 | 實體：煞車踏板總成（BR）、加速踏板總成（ACC） |
