## 文件與設定問題

### D-01 本機 `.env` 只讀取 API Key

- **現況**：README 與 `docs/安裝與啟動.md` 表示 `.env` 可設定 `GRAPHRAG_API_BASE`、`GRAPHRAG_CHAT_MODEL`、`GRAPHRAG_EMBEDDING_MODEL`。程式只以 `dotenv_values` 讀取 API Key（`connections.py` 的 `_dotenv_api_key`），未呼叫 `load_dotenv`，因此本機 `.env` 的 Base URL 與模型不會生效。Docker 使用 `--env-file` 時不受影響。
- **做法（擇一）**：
  - A. 程式改為從 `.env` 讀取全部四個設定，與文件一致，並補測試。
  - B. 文件改為說明本機 `.env` 只提供 API Key，其餘設定請用環境變數或 0-1 頁面。
- **驗收**：本機只放 `.env` 時，0-1 頁面顯示的 Base URL 與模型與文件描述一致。

### D-02 連線設定讀取優先順序不一致

- **現況**：API Key 依序讀取環境變數 → `PROJECTS_ROOT/.connection.json` → `.env`。Base URL 與模型則是只要 `.connection.json` 存在就完全忽略環境變數。在後台儲存過一次後，再改環境變數中的模型不會生效；`docs/交接紀錄.md` 只描述 API Key 的順序。
- **做法**：決定統一的優先順序（建議與 API Key 相同），再同步調整程式、測試與 `docs/安裝與啟動.md`。與 D-01 一起處理。
- **驗收**：`tests/test_connections.py` 涵蓋四個設定在三種來源下的優先順序；文件明列順序。

### D-03 README Linux 同時啟動兩入口會搶連接埠

- **現況**：README「非 Docker 啟動方式」的 Linux 指令沒有為兩個入口指定不同連接埠，兩者都使用預設的 7860，後啟動者會失敗。Windows 指令則已分開使用 7860 與 7861。
- **做法**：Linux 管理後台指令加上 `GRADIO_SERVER_PORT=7861`。
- **驗收**：照 README 在 Linux 同時啟動兩入口皆成功。

### D-04 使用指南與策略文件的指標說明過時

- **現況**：`docs/使用指南.md` 常見狀況提到「Recall／MRR」，但 0-5 顯示的是 Evidence Hit Rate、Evidence Precision、Document Hit Rate；Recall／MRR 只存在於已隱藏的舊分頁。`docs/檢索實驗與策略參數.md` 稱「沒有排序後的來源排名」時標示不可計算，但程式註明這三個指標不使用排名。
- **做法**：改寫為目前三個指標，以及實際的「不可計算」條件（缺 Gold 頁碼、策略來源無法映射，例如 Global 社群報告）。
- **驗收**：文件中的指標名稱與 0-5 摘要表欄位一致。

### D-05 README 常見問題提到已隱藏的勾選框

- **現況**：README「如何降低開發測試成本」建議「不要勾選重新執行系統回答」，但該勾選框位於隱藏的「自動評測（已整合）」分頁，使用者看不到。
- **做法**：改為對應 0-4／0-5 現行流程的說法（回答與評測分開執行，評測只使用既有回答）。若 F-01 移除隱藏分頁，一併確認。
- **驗收**：README 提到的控制項都能在介面上找到。

### D-07 LLM prompt 未使用英文

- **現況**：AGENTS.md 規則 4 要求送交 LLM 的 prompt 使用英文，但 `question_generation.py` 的題目生成 prompt 與 `automatic_evaluation.py` 的評測 prompt 為中文。
- **做法**：將指令改寫為英文，保留「輸出繁體中文」的要求與既有中文驗證（`_contains_chinese`）；檢查 `retrieval_experiments.py` 的 Judge prompt 是否也需調整。更新 prompt 版本號與相關測試。
- **驗收**：所有 prompt 指令為英文；生題輸出仍通過繁體中文驗證；相關測試通過。

### D-08 交接紀錄搬移後連結失效、欄位名稱過時

- **現況**：第 3 行失效的相對連結已隨 D-06 修正。內文的題目集欄位 `reference_answer`、`answer` 與現行格式 `expected_answer` 不同，現行匯入會拒絕舊欄位，尚未處理。
- **做法**：在欄位說明旁註明已由 `docs/題目集格式.md` 取代。
- **驗收**：連結可開啟；讀者不會依舊欄位建立題目集。

### D-09 範例題目集答案為佔位文字

- **現況**：`docs/檢索實驗格式範例.json` 兩題的 `expected_answer` 都是同一句「先確認設備已關閉，準備指定工具，並依序完成安全檢查。」，與題目內容無關。範例 PDF 檔名也與 `docs/題目集格式.md` 不同。
- **做法**：換成與題目相符的答案，並統一兩份文件的範例檔名。
- **驗收**：範例可通過匯入驗證，且內容合理。

### D-10 README 安裝指令未指定 Python 版本

- **現況**：README 使用 `python3 -m venv`，在 `python3` 為 3.10 的環境會因需求 `>=3.11` 而安裝失敗。`docs/安裝與啟動.md` 則寫死 `python3.12`。
- **做法**：兩份文件統一寫為 `python3.12`（或 `python3.11`），並註明最低需求與版本檢查方式。
- **驗收**：兩份文件的安裝指令一致。

### D-11 Dockerfile 的 `uv` 使用 `latest`

- **現況**：README 稱依賴為「已驗證的固定版本」，但 Dockerfile 以 `ghcr.io/astral-sh/uv:latest` 取得 `uv`。
- **做法**：固定 `uv` 映像版本，或在 README 說明只有 Python 套件固定版本。
- **驗收**：重新建置映像不因 `uv` 版本變動而改變行為。

### D-12 `.dockerignore` 列出不存在的檔案

- **現況**：`.dockerignore` 排除 `UI設計書.md`、`專案進度.md`，兩者皆不存在。
- **做法**：移除這兩行，或在建立這些檔案後保留。
- **驗收**：`.dockerignore` 只列出實際需要排除的項目。
