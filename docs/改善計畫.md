# 改善計畫

本文件追蹤專案的改善項目。新增、調整項目時，同步更新「狀態總覽」與對應項目的現況、做法及驗收標準；新發現的問題也記錄在此。

項目完成後，在狀態總覽的「結果」欄寫一句做法與驗收結果，並附上 commit hash，然後刪除下方該項目的細節段落。完整改動可由 commit 查詢。

狀態：`待辦`、`進行中`、`待確認`（需先決定方向）、`完成`、`不處理`

## 文件與設定問題

### D-03 README Linux 同時啟動兩入口會搶連接埠

- **現況**：README「非 Docker 啟動方式」的 Linux 指令沒有為兩個入口指定不同連接埠，兩者都使用預設的 7860，後啟動者會失敗。Windows 指令則已分開使用 7860 與 7861。
- **做法**：Linux 管理後台指令加上 `GRADIO_SERVER_PORT=7861`。
- **驗收**：照 README 在 Linux 同時啟動兩入口皆成功。

### D-04 使用指南與策略文件的指標說明過時

- **現況**：`docs/使用指南.md` 常見狀況提到「Recall／MRR」，但「4 檢索實驗」顯示的是 Evidence Hit Rate、Evidence Precision、Document Hit Rate；Recall／MRR 只存在於已隱藏的舊分頁。`docs/檢索實驗與策略參數.md` 稱「沒有排序後的來源排名」時標示不可計算，但程式註明這三個指標不使用排名。
- **做法**：改寫為目前三個指標，以及實際的「不可計算」條件（缺 Gold 頁碼、策略來源無法映射，例如 Global 社群報告）。
- **驗收**：文件中的指標名稱與「4 檢索實驗」摘要表欄位一致。

### D-05 README 常見問題提到已隱藏的勾選框

- **現況**：README「如何降低開發測試成本」建議「不要勾選重新執行系統回答」，但該勾選框位於隱藏的「自動評測（已整合）」分頁，使用者看不到。
- **做法**：改為對應「3 自動問答測試」／「4 檢索實驗」現行流程的說法（回答與評測分開執行，評測只使用既有回答）。若 F-01 移除隱藏分頁，一併確認。
- **驗收**：README 提到的控制項都能在介面上找到。

### D-08 交接紀錄搬移後連結失效、欄位名稱過時

- **現況**：第 3 行失效的相對連結已隨 D-06 修正。內文的題目集欄位 `reference_answer`、`answer` 與現行格式 `expected_answer` 不同，現行匯入會拒絕舊欄位，尚未處理。
- **做法**：在欄位說明旁註明已由 `docs/題目集格式.md` 取代。
- **驗收**：連結可開啟；讀者不會依舊欄位建立題目集。

### D-09 範例題目集答案為佔位文字

- **現況**：`docs/檢索實驗格式範例.json` 兩題的 `expected_answer` 都是同一句「先確認設備已關閉，準備指定工具，並依序完成安全檢查。」，與題目內容無關。範例 PDF 檔名也與 `docs/題目集格式.md` 不同。
- **做法**：換成與題目相符的答案，並統一兩份文件的範例檔名。
- **驗收**：範例可通過匯入驗證，且內容合理。

### D-10 README 安裝指令未指定 Python 版本

- **現況**：README 使用 `python3 -m venv`，在 `python3` 為 3.10 的環境會因需求 `>=3.11` 而安裝失敗。`docs/安裝與啟動.md` 則寫死 `python3.12`。

- **現況**：Samsung S25「3 自動問答測試」共有 12 題被判錯，其中約 8–9 題主要是答案超出題目範圍；手冊頁級 Text Unit（例如 `p0037-b01`）包含多個小節，讓同頁內容容易被一起檢索及生成。Local 路由 5 題中錯 2 題，至少 Q7 的答案在 p63–64，而檢索只取到 p62；系統據此回答「資料未說明」。Q11、Q25 及部分 Q14、Q16 因同一小節內補充注意事項不完整而出現 judge 分歧。Q9 合併不同小節後改變操作順序。Q19、Q22 的來源編號各差一頁。平均每題 58 秒，最慢 100 秒。
- **規劃原則**：以「題目對應的小節」作為答案證據範圍：同一小節的步驟、列表、附註、限制與後續分支要完整保留；不同小節要分開檢索／組織，不因同頁而合併。引用必須對應實際來源，不以頁面印刷頁碼猜測 context ID。檢索補救須有上限，避免漏召回改善造成每題延遲與模型呼叫數大幅增加。

### F-45 長時間工作可停止：執行中按鈕變為停止按鈕

## 程式錯誤

### B-06 建圖中斷後殘留鎖檔，專案卡在 INDEXING

- **現況**：
  - Samsung 專案 10-26 15:42 開始的建圖，在 `indexing.log` 56/206 時中斷：程序被直接終止，`IndexingService.build` 的 `finally` 沒有執行，留下空的 `graphrag/.indexing.lock`，狀態也停在 INDEXING。
  - 之後畫面一直顯示「建圖中」，「2 問答測試」等查詢被拒；按建圖則出現「此專案已有建圖工作正在執行」，因為 `_acquire_lock`（`indexing.py`）只用 `O_EXCL` 判斷鎖檔是否存在，無法分辨過期的鎖。
  - 中斷的建圖留下半套輸出：`text_units.parquet`（10-26）缺 `human_readable_id` 欄位，比 `entities` 等輸出（10-25）新，導致 `EvidenceService.from_context` 讀取失敗、Evidence 全空、Evidence 指標不可用，`context["_evidence_warning"]` 是唯一線索。
  - 2026-11-08 已處理當下狀況：狀態因重新前處理變為 READY；確認沒有建圖程序後，手動刪除殘留鎖檔，可以重新建圖。重新建圖成功後，半套輸出會整份換掉。程式根因尚未修正。
- **做法**：
  1. 建圖期間對鎖檔持有排他 `flock`，並寫入 PID 與開始時間供排查。程序被終止時核心會自動釋放 `flock`，因此鎖檔存在但沒人持有（含舊格式、內容空白）就視為過期鎖並取代，同時在 `indexing.log` 註明清除了過期鎖與原持有者；仍有人持有時維持目前的錯誤訊息。比起只比對 PID，`flock` 不會因 PID 被重用（例如容器重啟後 PID 相同）而誤判。刪除專案、移除 PDF、修改頁面內容等原本只看鎖檔是否存在的檢查，也改為判斷是否有人持有。
  2. 管理後台啟動時，若專案狀態為 INDEXING 但沒有活著的鎖持有者，就把狀態改為 FAILED 並清除過期鎖。若有 `.last-successful-output`，比照 `build` 的失敗流程還原成 `output`。
  3. （選做）`EvidenceService` 讀 `text_units.parquet` 缺欄位時，改為明確提示「索引輸出不完整，請重新建圖」，而不是只留在 `_evidence_warning`。
  4. 補回歸測試：殘留空鎖檔或 PID 已不存在時可以建圖；PID 仍存在時被擋下；啟動時 INDEXING 且無鎖持有者會改為 FAILED 並還原輸出。
- **進度**（2026-11-08）：1～4 已完成。`indexing.py` 新增 `recover_interrupted_builds`，由 `create_app` 啟動時呼叫；`projects.py` 新增 `indexing_lock_held`／`project_indexing_locked` 供各處共用；`EvidenceService` 讀不到 `id`／`human_readable_id` 時改丟「索引輸出不完整…請重新建圖」。`test_indexing.py` 新增以子程序持鎖後 SIGKILL 的實際中斷情境、跨程序擋下第二個建圖、空白鎖檔取代、啟動復原與持鎖者仍在時不復原等案例，`test_projects.py`、`test_evidence.py` 補對應案例；完整測試 380 項通過，管理後台已自動重啟。未完成：commit、Samsung 重新建圖並確認 Evidence 可正常對應。
- **驗收**：模擬建圖程序被終止後，不必手動刪檔即可重新建圖，狀態不會停在 INDEXING；同時有兩個建圖時仍會擋下第二個；相關測試通過。Samsung 重新建圖後 `text_units.parquet` 含 `human_readable_id`，Evidence 可正常對應。

### T-03 新增對應評測弱點的 Samsung S25 題組

- **現況**：既有 30 題以單本手冊事實查找為主，無法針對 F-42、F-43 的弱點分別量測。
- **做法**：新增 30 題，依弱點分組：

| 弱點 | 題號 | 設計方式 |
|---|---|---|
| 名稱相近的功能 | 1–7 | 強制重啟和關機用同一組按鍵；截圖工具列；螢幕錄製；繪圖智慧助理；相簿類型；刪除聯絡人；懸浮翻譯 |
| Local 找錯段落 | 8–13 | 臉部註冊、指紋解鎖、合併聯絡人、封鎖號碼、安全資料夾、Samsung Pass。都是放在設定或 App 深層的步驟，而且前後頁有很像的內容 |
| 注意事項很多 | 14–19 | 無線充電、防水、指紋效能、臉部辨識須知、無線電力共享、充電過熱 |
| 有後續分支 | 20–23 | 關機加上重新啟動、移動或複製到安全資料夾、隱藏後再次開啟、解除安裝時備份 |
| 容易多答 | 24–27 | 答案範圍很窄，但旁邊緊接著容易被一起答進去的段落，例如國際電話、拒接時傳訊息、電量上限、變更鎖定方式 |
| 機型差異 | 28–30 | S Pen 卸除、只有 S24 Ultra 的 S Pen 要充電、磁性物品對 S25 和 S24 Ultra 的影響不同 |

- **進度**：題組已建立於 [`Samsung_S25_弱點題組.json`](Samsung_S25_弱點題組.json)，題號與上表分組一致；每題的參考答案都依手冊原文撰寫並標明頁碼，已確認可以匯入。尚未實際評測。
- **驗收**：題組每題都有參考答案與可在來源 Metadata 找到的文件／頁碼；能以「3 自動問答測試」完成評測，並依上表分組統計正確率。
