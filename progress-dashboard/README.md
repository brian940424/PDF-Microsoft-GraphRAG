# 開發進度指揮中心

以策略遊戲風格的 3D 地圖呈現本 repo 的開發進度。使用 Next.js（App Router）與 React Three Fiber，由伺服器端直接讀取上一層 repo 的檔案與 git，畫面每 20 秒自動更新。

## 啟動

需要 Node.js 20 以上（本機以 nvm 安裝的 v24 驗證）。

```bash
cd progress-dashboard
npm install
npm run dev          # 開發模式：http://127.0.0.1:3100
# 或
npm run build && npm start
```

預設讀取上一層目錄；要指向其他 checkout 時設定 `REPO_ROOT=/path/to/repo`。伺服器只綁定 127.0.0.1，因為「執行測試」會在本機執行 pytest。

## 地圖元素與資料來源

視覺上採用明亮的等角（正交）積木風格：白色圓角卡片、藍色主色、低多邊形 3D 模型，比喻為「開發工地」。

| 元素 | 意義 | 資料來源 |
|---|---|---|
| 分區與地塊 | 每個改善項目一塊地，依類別第一段分區 | `docs/改善計畫.md` 狀態總覽表格 |
| 藍色倉庫 | 完成；橘點＝已完成但未提交；大小依優先度 | 同上 |
| 鷹架＋塔吊＋堆高機 | 進行中 | 同上 |
| 棧板與交通錐 | 待辦；待確認另插黃色定位圖釘 | 同上 |
| 測試貨櫃場 | 每個測試模組一個貨櫃，通過為青綠、失敗為紅色並插紅色圖釘 | 按「執行 pytest」以 `.venv/bin/python -m pytest` 執行，結果快取於 `.cache/tests.json` |
| 道路上的卡車 | 最近 7 天的提交（3～8 台），貨櫃色帶代表提交類型 | `git log --shortstat` |
| KPI 卡、導覽列 | 計畫完成、測試通過、本週提交、分支與未提交變更 | 同上與 `git status --porcelain` |
| 任務追蹤 | 待開工 → 施工中 → 完工 → 已提交 的流程；未選取時顯示各階段數量 | 改善計畫狀態與「結果」欄的 commit／未提交標記 |
| 交接・建議下一步、交接分頁 | 「目前狀態」段落 | `docs/交接紀錄.md` |

點擊地塊、貨櫃、卡車或表格列會讓鏡頭移過去並在右側卡片顯示細節；右側地圖控制可縮放、旋轉 45° 與回到全景。任務分頁的狀態徽章可篩選地塊。
