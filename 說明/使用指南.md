# 使用指南

## 建立專案並匯入文件

1. 開啟管理後台，在「0-0 專案設定」建立專案，然後選取並開啟。
2. 在「0-1 連線設定」輸入 API Base URL 與 API Key，選擇 Chat、Embedding 模型並測試連線。
3. 前往「0-2 文件與建圖」匯入 PDF。每份文件可以分別設定忽略頁首／頁尾比例及頁面範圍；起始頁和結束頁使用從 0 開始的索引，結束頁包含在範圍內。
4. 執行前處理並確認文件狀態，再建立 Graph。建圖日誌會持續更新。若中斷或狀態停在索引中，先查看該頁日誌及專案的 `graphrag/` 狀態檔，再決定是否重建。

建圖會呼叫 LLM 與 Embedding API，費用與等待時間依文件量和供應商計價而異。掃描影像 PDF 目前不保證可由文字抽取取得內容。

## 單次問答與 Evidence

在「0-3 問答測試」輸入問題，選擇回答模型、四種檢索策略之一與回答格式，再送出查詢。回答以外，頁面也會顯示查詢 Context、Evidence 清單及選取證據的原文（可取得時包含文件、頁碼、Chunk 等資訊）。Evidence 是程式從 GraphRAG 查詢回傳的 Context 解析，不是模型回答中自行生成的來源標籤。

一般入口只提供使用者問答，管理後台需先將專案建圖完成並啟用一般使用者查詢。

## 自動問答測試（0-4）

自動問答頁分為生成題目、生成回答和評測回答幾個步驟：

1. 匯入題目集，或設定每份 PDF 的題數與生題模型後生成題目。生題和答案來源可在題目表格修改，並匯出 JSON。
2. 設定回答模型、檢索方式、回答格式及回答請求並行數，執行生成回答。生成完成前評測不可執行。
3. 設定評測模型及評測並行數，再執行評測。結果表顯示系統回答、標準答案、判斷和理由。
4. 人工調整判斷時，該筆評判理由會清空，正確率會自動重算。

生成答案與評測分開執行；回答會保存於目前專案，重新開啟專案後仍可繼續評測。

## 檢索實驗（0-5）

1. 匯入一個或多個題目集。再次匯入時會以所選題目集取代原有匯入題目，不會累加舊題目。
2. 新增實驗組後，在各組卡片內選擇回答模型、策略與回答格式。選擇策略後會顯示其專屬參數；參數是依實驗組和策略分開保存的。
3. 設定全域評測模型、評分方式和測試最大並行請求數。先按「檢索並生成答案」，完成後再按「評測答案」。可停止實驗，已完成逐題結果會保留。
4. 查看實驗組摘要、實驗組 × 題目集摘要和逐題結果。逐題等級 0／1／2 可人工修改並更新摘要。
5. 匯出精簡摘要 JSON 和逐題結果 JSON。

策略可調項與指標意義詳見[檢索實驗與策略參數](檢索實驗與策略參數.md)。題目集資料欄位詳見[題目集 JSON 格式](題目集格式.md)。

## 常見狀況

- 「沒有可選專案」：確認專案已開啟；一般入口另要求索引完成並啟用查詢。
- 「尚未生成答案」：先在檢索實驗完成回答生成，等待狀態顯示完成後再評測。
- Recall／MRR 等來源指標不可計算：通常是該策略沒有可可靠映射的排序來源，或題目缺少來源頁碼。系統不會推測排名或虛構命中。
- API Key 重啟後消失：確認環境變數、`.env` 或 `PROJECTS_ROOT/.connection.json` 設定，並確保重新啟動時使用相同 `PROJECTS_ROOT`。
